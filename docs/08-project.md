# 阶段 8：综合项目

目标：在两到三周内独立完成一个规模可控、能构建、能测试、能交付的 Rust 项目。

不要一开始选择过大的题目。项目应有一个主要用户、一条核心流程和明确的完成条件。

## 1. 选择方向

### 方向 A：命令行日志分析器

输入一个或多个日志文件，输出级别统计、时间范围和高频错误。

可以练习：

- 命令行参数
- 文件和流式 I/O
- 字符串解析
- 迭代器和集合
- 并行处理多个文件

### 方向 B：待办事项 Web API

提供新增、查询、完成和删除任务的 HTTP API。

可以练习：

- Tokio 与 Axum
- Serde JSON 序列化
- SQLx 数据库访问
- 统一错误响应
- 集成测试

### 方向 C：本地键值存储

实现 `set`、`get`、`remove` 和数据持久化。

可以练习：

- 二进制或文本格式
- 文件 I/O
- 索引结构
- 崩溃恢复
- 并发访问

第一次综合项目推荐方向 A，因为外部依赖少，可以把注意力放在 Rust 和工程结构上。

## 2. 项目立项

开始编码前写一个短的 `README.md`：

```markdown
# 项目名称

一句话说明它解决什么问题。

## 使用方法

给出一条可以运行的命令和预期输出。

## 第一版功能

- 必须完成的功能 1
- 必须完成的功能 2
- 必须完成的功能 3

## 暂不实现

- 明确排除的功能
```

“暂不实现”很重要，它能阻止项目无限扩大。

## 3. 第一周：完成最小闭环

目标是让核心流程尽快跑通。

1. 第 1 天：建立项目，定义输入和输出示例。
2. 第 2 天：定义核心数据结构和错误类型。
3. 第 3～4 天：实现不依赖 I/O 的核心业务逻辑。
4. 第 5 天：添加命令行或 HTTP 入口。
5. 第 6 天：连接真实文件、数据库或网络。
6. 第 7 天：补齐正常流程测试。

推荐依赖方向：

| 需求 | 常用 crate |
| --- | --- |
| 命令行参数 | `clap` |
| JSON | `serde`、`serde_json` |
| 日志 | `tracing`、`tracing-subscriber` |
| 异步运行时 | `tokio` |
| Web API | `axum` |
| 数据库 | `sqlx` |

不要一次性添加全部依赖，只在功能需要时添加。

## 4. 第二周：可靠性和可维护性

1. 处理空输入、错误格式、文件不存在等边界情况。
2. 去掉业务路径中没有充分理由的 `unwrap()`。
3. 把核心逻辑与 I/O 分开。
4. 为错误路径添加测试。
5. 给公共 API 添加文档注释。
6. 使用 Clippy 清理常见问题。
7. 检查模块命名和职责是否清楚。

建议至少包含：

- 5 个核心逻辑单元测试。
- 3 个错误或边界情况测试。
- 2 个完整流程集成测试。

测试数量不是最终目标，每个测试都应保护一条有意义的行为。

## 5. 第三周：交付

如果项目需要第三周，集中完成：

1. 性能测量和必要优化。
2. 结构化日志和配置。
3. 发布构建。
4. 完整 README。
5. 在干净环境中重新执行安装和运行步骤。

不要凭感觉优化。先测量，再处理确实影响目标的瓶颈。

构建发布版本：

```bash
cargo build --release
```

最终检查：

```bash
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo doc --no-deps
```

## 6. 推荐项目结构

中小型项目可以从下面的结构开始：

```text
project/
├── Cargo.toml
├── README.md
├── src/
│   ├── lib.rs
│   ├── main.rs
│   ├── error.rs
│   ├── model.rs
│   └── service.rs
└── tests/
    └── main_flow.rs
```

- `lib.rs` 导出可测试的核心能力。
- `main.rs` 只处理入口、配置和输出。
- `error.rs` 定义应用错误。
- `model.rs` 定义领域数据。
- `service.rs` 实现业务流程。

这只是起点。小项目不需要强行创建所有文件，大项目则应该按实际职责继续拆分。

## 7. 项目验收清单

- README 说明了用途、环境要求、构建、运行和测试命令。
- 新用户可以只看 README 成功运行项目。
- 所有外部输入都经过验证。
- 错误信息说明发生了什么，而不是只输出“失败”。
- 核心业务逻辑不与终端、网络或数据库强绑定。
- 没有不必要的 `clone()` 和共享可变状态。
- 至少包含正常、边界和错误三类测试。
- 格式化、Clippy、测试和文档命令全部通过。
- 能在 5 分钟内讲清项目结构、数据流和关键技术选择。

## 8. 完成之后

完成第一个项目后，根据目标选择深入方向：

- 后端：深入 Tokio、Axum、数据库、可观测性和服务部署。
- 系统编程：深入操作系统、网络协议、unsafe Rust 和性能分析。
- 嵌入式：学习 `no_std`、硬件抽象层和交叉编译。
- WebAssembly：学习 `wasm-bindgen` 和浏览器互操作。
- 工具开发：深入 CLI 设计、文件格式、并行处理和跨平台发布。

此时再阅读官方教程的高级内容和实际开源项目，会比一开始直接阅读大型代码库更容易吸收。
